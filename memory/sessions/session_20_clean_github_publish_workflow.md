# Session Memory: Clean GitHub Publish Workflow

Status: complete
Last updated: 2026-08-09 UTC
Thread/task: main agent version-management gate

## Scope

This session owns the reusable GitHub clean-publish workflow. It converts the
one-off clean remote upload into a repeatable, auditable path for future core
experiment-code updates.

It does not change experiment results, run model training, rewrite the local
server-working history, or store any plaintext credentials.

## Current State

- The GitHub repository `zwtbb/multidatasets_mdd` already has a clean `main`
  lineage created from audited snapshots.
- Local `/root/autodl-tmp/main` still contains old server-working commits with
  generated Phase 2 result blobs in history, so it must not be pushed directly.
- Added `scripts/publish_clean_github_snapshot.py`, a dry-run-by-default helper
  that publishes committed source snapshots onto the clean remote lineage.
- Added `docs/github_publish_workflow.md` and linked it from `README.md`.

## Key Decisions

- Future GitHub updates should use the helper or an equivalent verified clean
  publish path, not direct pushes from the old local `main` history.
- The helper checks the publish tree for banned Phase 2 baseline artifacts,
  bulky prediction/embedding/model paths, and plaintext credential-like content
  before committing in the temporary clean repo.
- Authentication should remain token/SSH/`gh auth login` based. Plaintext
  GitHub passwords must not be used in commands, files, memory, Git config, or
  shell history.
- Baseline reproduction result artifacts stay local-only by default. GitHub
  should carry the core reproducible experiment skeleton and paper-critical
  lightweight reports, not bulky generated outputs.

## Blockers And Risks

- The helper publishes from a committed source ref. Uncommitted tracked changes
  are intentionally refused unless `--allow-dirty` is explicitly provided, and
  even then the archive still uses `--source-ref`.
- The helper's path denylist is conservative. If a small summary is rejected by
  name, review content first and rename only if it is not row-level,
  subject-level, raw-text-bearing, or otherwise local-only.
